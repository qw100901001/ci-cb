# 00 · 这个项目怎么讲（面试话术）

> 面试官问"介绍一个你有代表性的项目"时，按下面的骨架讲，控制在 2 分钟以内。

## 一句话版本

"我做了一个微前端架构的练习项目：用 pnpm + Turborepo 管理的 monorepo，Vue3 做基座，React 和 Vue3 两个技术栈的子应用通过 qiankun 接入，从工程化、通信到 Docker 化部署和 GitHub Actions 流水线完整跑通了一遍。"

## STAR 展开

**S（背景）**
中大型团队常见痛点：多个团队、不同技术栈（有的页面是 React 有的页面是 Vue）、项目迭代节奏不一致，揉在一个单应用里会互相拖累；拆成多个独立仓库又面临公共代码复用和统一部署的问题。

**T（任务）**
我给自己定的目标是搭一套微前端的完整闭环：不是只跑个 demo，而是把**工程化管理（monorepo）、主子应用通信、生产部署（同域 nginx）、CI/CD 流水线**这四件事全部打通。

**A（行动）**
- 用 pnpm workspace + Turborepo 管理 3 个应用和 1 个共享包，共享类型和工具函数通过 `workspace:*` 协议复用；
- Vue3 基座负责菜单布局、路由分发和登录态（Pinia），qiankun 注册两个子应用，按 `activeRule` 懒加载；
- 通信走两条路：主→子用 qiankun props（传 `getUserInfo` 函数保证实时性），子→主用 `initGlobalState` 全局状态上报事件；
- 部署上做同域 nginx 方案，三个应用构建产物打进一个镜像，多阶段构建把镜像从 1G 级压到 50MB 级；
- GitHub Actions 上跑两条流水线：CI 做类型检查/单测/构建，CD 构建镜像推 GHCR。

**R（结果）**
- 整套流水线命中缓存后 1 分钟内跑完；
- 微前端解决了跨技术栈集成问题，子应用独立开发、独立构建，任何一端发版不影响其他端；
- 过程中踩了几个真实的坑（见下），都定位到了原理层面并解决。

## 三个"踩坑故事"（面试官最爱听的）

面试官问"遇到什么难点"时，讲这三个，每个都真实发生在本仓库：

### 坑 1：Vite 子应用接入 qiankun 报 cheerio 导出错误

**现象**：`vite build` 直接失败，报 `"default" is not exported by cheerio`。
**定位**：vite-plugin-qiankun 依赖 cheerio 解析 HTML，而 cheerio 新版（1.0 正式版之后）改成了纯 ESM 且没有 default export，rollup 打包时 interop 失败。
**解决**：在根 `package.json` 用 pnpm 的 `overrides` 把 cheerio 锁回 `1.0.0-rc.12`。
**话术升华**："这个问题本质是**第三方库的依赖升级破坏了间接依赖它的包**。npm 生态里 semver 范围解析到的版本会随时间漂移，所以生产项目要锁 lockfile、要有 CI 兜底。pnpm 的 overrides 是比 fork 上下游更轻的干预手段，类似的还有 resolutions（yarn）。"

### 坑 2：主应用状态更新后子应用拿到的是旧值

**现象**：如果注册微应用时把用户信息当**值**传进 props，主应用切换用户后，已挂载的子应用不会更新。
**解决**：props 传**函数** `getUserInfo: () => userStore.userInfo`，子应用每次渲染实时调用。
**话术升华**："这和 React 里常见的'传值 vs 传回调'是一个思想——跨应用边界的数据传递，宁可传 getter 也不要传快照。"

### 坑 3：子应用部署后白屏（开发环境正常）

**现象**：dev 下一切正常，nginx 部署后子应用 404/白屏。
**定位**：qiankun 生产模式的 entry 是 `/sub-react/`，而子应用构建时 `base` 还是默认 `/`，静态资源全部 404。
**解决**：vite.config 里 `base: mode === 'production' ? '/sub-react/' : '/'`，同时 nginx 的 `location /sub-react/` 配 `try_files` 做 SPA fallback。
**话术升华**："微前端部署不是'丢上服务器'就行，**子应用挂载路径、静态资源 base、路由 fallback 三者必须对齐**，这比单应用部署的约束多一层。"

## "如果上生产还缺什么"（体现视野的加分回答）

- 子应用路由同步（当前子应用无内部路由，真实项目要在 base 挂 `createWebHistory('/sub-react/')` 并处理路由同步）；
- 公共依赖抽离（vue 只在基座打一份，子应用 external）；
- 鉴权下沉（统一网关/token 注入 props）；
- 监控（子应用加载失败上报、沙箱报错捕获）；
- 发布灰度（按 activeRule 指到新旧版本 entry 实现金丝雀）。
